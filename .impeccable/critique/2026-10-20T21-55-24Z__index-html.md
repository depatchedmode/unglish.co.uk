Unglish website review — 20 October 2026

Unglish already has a voice worth preserving. The website does not yet give the whole project an equally strong form: it introduces a manifesto and historical releases, hides the playable work, omits the active generator, and currently sends collectors to broken Highlight pages. The strongest direction is a small literary publication with a living word specimen at its center.

Scope: index.html, styles.css, iterations/a.html, iterations/a-preview.html; live unglish.co.uk and outgoing project/mint links; local /Users/ryanbetts/Code/unglish/word-generator. This is a review, not an implementation. Production source files are unchanged.

What works

- The writing is specific to Unglish. “Squint your ears,” “impregnababble,” vowel-based versioning, and “Only me and you” carry the project's humor and ambition. Preserve that voice.
- Plain documents, native links, system fonts, local CSS, and a self-contained artwork already provide a strong web-platform foundation.
- A generated word with pronunciation and a melody is a distinctive artistic object. That encounter deserves the first and strongest visual emphasis.

Five priorities

1. P0 — The collecting handoff currently fails.

All four Highlight sponsorship links at iterations/a.html:71,76,81,86 rendered “Unable to load collection”; their collection API requests returned HTTP 400 while the enclosing HTML returned 200. The profile link at index.html:33 rendered “Profile unavailable.” These observations establish broken visitor journeys, not the status of the underlying contracts or tokens. The Teia page loaded and exposed a collection control; no transaction or on-chain supply verification was performed.

Resolve working collection URLs and verify them by rendering, not merely checking HTTP 200. Until verified, use an honest dated availability label. Give each edition its actual artistic distinction, named chain, release date, artwork access, and a destination-specific collection link. The four cards presently offer names and identical invitations, without enough context to choose. Do not invent dialect differences: they were not established by this review.

2. P1 — The current word generator is absent from the site's story.

The homepage's latest listed release is January 2024. It has no route to the current generator, source, or demo. Its public repository and demo respond successfully.

A newcomer has to infer that “unglish a” contains playable artwork. At 1280×800, the first homepage link begins at y=863; at 390×844, around y=1046. Show a specimen immediately, explain the premise in one clear sentence, and make the engine and editions discoverable as related parts of the project. Move the unavailable Dictionary into a dated statement of intent until there is something to explore.

3. P1 — The specimen needs accessible controls and reliable narrow-screen layout.

The iframe has no title. Its generated document has no semantic playback, voice, or pitch controls. Tab does reach its body and Space operates playback, but there is no visible focus or discoverable playback state there. Native outer links and the New Word button retain their normal keyboard behavior.

The interface relies on a mouse event and hidden keyboard commands. The pronunciation measures approximately 4.5–6.5 CSS pixels in tested mobile-sized viewports. At 390px, an ordinarily generated “mneerrts” extended past the preview edges and was cropped. Height-based font sizing and padding inside a tall narrow iframe cause this; overflow:hidden conceals the result. A separate 375px test cropped 12 of 15 artwork frames, which is not a claim that 12 of 15 words were clipped. At 320px, the large mint-status heading makes the iteration document 343px wide.

Provide native, labeled Speak, Sing/Stop, and Another word buttons beside the specimen. Show state, offer readable voice/pitch controls, and handle unavailable speech visibly. Size against available width; allow deliberate wrapping; keep pronunciation at a normal reading size. Static text should remain meaningful without JavaScript.

There is also a confirmed pitch bug: after raising pitch to its limit, lowering it has no effect because the guard blocks both directions. Synthetic keyup events exercised the actual code while speech utterances were recorded; Escape restores the offset. Real Space/Escape tests confirmed that Escape resets pitch/voice but does not stop the timer. A visible Stop remains essential; Escape stopping is a recommended improvement, not a behavior currently promised.

4. P1 — Accessibility and document setup contradict the site's standards claim.

All three documents omit their language. Both editorial pages omit the doctype and explicit charset and contain duplicate titles. Both render in BackCompat/quirks mode. Live hosting currently supplies UTF-8 correctly; a simple local server decodes them as Windows-1252. That is portability fragility, not demonstrated live production text corruption.

Both marquees move continuously without pause or stop. They need stationary copy or user-controlled motion. Blink does not actually flash in the tested browser. Marquee and blink are obsolete non-conforming authoring features in the HTML Standard.

Computed contrast is insufficient for several real text states: dark marquees are 2.139:1; homepage green status labels on black are 4.088:1; light preview IPA is 3.623:1, against a 4.5:1 requirement for normal text. Dark large headings are 3.825:1 and pass their 3:1 threshold. Fix explicit foreground/background pairs, not every muted color indiscriminately.

Use standards-mode HTML with language, early UTF-8, one title, main/navigation/footer where appropriate, and a coherent heading outline. Recheck layout after adding the doctype because quirks-mode layout can change. Correct the h3→h5 skip and distinguish sponsor links by dialect.

Relevant source: index.html:1,34,40,50; iterations/a.html:1,40,47,65–85; styles.css:10–16,90–104; iterations/a-preview.html:162–165,237.
Suggested follow-up: /impeccable harden.

5. P2 — The visual hierarchy has not caught up with the literary ambition.

The homepage title is about 90px on desktop against 16px reading text. Large greetings, monumental section headings, beveled borders, and marquees dominate the composition. At 390px, framing and padding consume 114px before definition-list indentation. The word itself arrives late.

Use a deliberate serif-first system-font stack, a quieter editorial type scale, comfortable reading measures, compact chapter headings, and generous but responsive margins. Give specimen typography the most emphasis. The bevel can survive as a restrained artifact motif. Keep intentional wordplay; repair accidental copy errors such as “innaugural,” “pronunctiation,” and “witll.”

The literary feeling should come from words, rhythm, annotation, and authorship. There is no need for a framework, animation library, or decorative stock imagery.

Relevant source: styles.css:20–26,38–68,100–120; index.html:49–83.
Suggested follow-up: /impeccable typeset, then /impeccable polish after substantive work.

Recommended structure

- Home: a word to encounter, a short statement of purpose, and clear routes into the project.
- Word generator: a focused native demo, what the current engine does, source and contribution links, and version information. Keep advanced diagnostics in the existing developer demo.
- Editions: dated generative publications, each with actual differences, provenance, preview, and verified collection destination. Explain the relationship between a frozen artwork and the evolving engine.
- Field notes / About: manifesto, influences, exhibitions, real progress, authorship, and participation. Publish prose and poetry when it exists; do not create another empty shelf.

The first-time reader should understand what Unglish makes. A contributor should reach its engine. A collector should know what an edition contains and where it can be collected. The current journey asks readers to carry a seven-part legend back to the specimen and ends with insufficiently distinguished collecting choices. Put the artistic encounter earlier and end with clear invitations.

Web-platform and dependency policy

The homepage is 5,440 bytes of HTML plus 2,272 bytes of CSS. It loads no framework, CDN script, or downloaded font. The 132,800-byte historical preview is self-contained but includes Highlight Generative Art Script 0.1.2 at a-preview.html:1–159 and relies on its RNG and trait APIs. No remote fetch dependency does not mean no third-party-origin code.

The current engine has no runtime dependencies. Its 38 production TypeScript modules transpile to 56 relative JavaScript module references, with no external runtime imports. Its APIs successfully generated deterministic seeded results in this review. Repeating generateWords(8, {seed:42, mode:"lexicon"}) reproduced results including benosable, remamfooc, unannofa, natutine, crills, and aund, with IPA and syllable data. This verifies that local revision's behavior, not cross-version stability.

Serve HTML, CSS, and pinned first-party Unglish ES modules from the site's origin. The generator can compile TypeScript in its own release workflow; the website can consume the released JavaScript without adding a site build framework. Development tooling is a distinct dependency boundary and is not presently dependency-free across the entire engine repository.

Keep readable specimens and prose in HTML and progressively enhance generation and speech. Save a specimen with its seed and engine/config version. SpeechSynthesis is a web API, but voice availability and delivery depend on browser/OS; this review did not establish offline speech or identical audio across devices.

For historical works, preserve the original artifact and document the embedded mint adapter, or create a distinct first-party preview beside it. Do not silently replace an old edition's generator with the current one. External source/mint links are destinations, not shipped runtime libraries. Verify data provenance before making a blanket claim that every embedded dataset is Unglish-owned. The engine's MIT license does not establish the license of every artwork.
